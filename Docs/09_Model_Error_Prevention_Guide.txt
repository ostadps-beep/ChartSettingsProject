================================================================================
DOCUMENT 09 — Model Error Prevention Guide
TYPE: Error Prevention Specification
================================================================================

PURPOSE
-------
This document defines rules to prevent model errors in understanding, interpreting,
and generating code for the Chart Settings Panel. It does NOT cover runtime errors
(system, GPU, .NET, Python/C++). It is a cross-cutting guardrail for all
implementation stages.

ERROR TYPES
-----------
1. JSON Misinterpretation
   - Adding undefined fields
   - Removing required fields
   - Changing structure or identifiers

2. UI Assembly Errors
   - Creating wrong controls
   - Misplacing modules
   - Ignoring sidebar order

3. Control Behavior Errors
   - Wrong binding direction
   - Missing validation
   - Ignoring dependencies

4. Button Logic Errors
   - Misinterpreting Apply/OK/Cancel/Reset
   - Saving JSON at wrong time
   - Resetting entire panel instead of module

5. Integration Errors
   - Wrong JSON → ViewModel → UI flow
   - Wrong UI → ViewModel → JSON flow
   - Adding dynamic fields at runtime

PREVENTION RULES
----------------
- The model must NOT invent new controls.
- The model must NOT add new JSON fields.
- The model must NOT remove required fields.
- The model must NOT change module order.
- The model must NOT modify button behavior.
- The model must NOT generate dynamic UI at runtime.
- The model must follow validation rules strictly.
- The model must respect dependency rules.

CHECKLIST
---------
Before finalizing output, verify:
- JSON structure matches specification
- Model-to-JSON mapping is unchanged
- UI modules match sidebar order
- Controls match defined behavior
- Buttons follow exact rules
- No extra code or fields were added
- No required structure was removed or modified

This checklist applies throughout implementation, not only at the end.
